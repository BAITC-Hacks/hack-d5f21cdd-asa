# Умный подбор event-подрядчиков (#79-lite)

Сервис принимает параметры заказа (город, дата, тип мероприятия, категория, бюджет, опционально длительность и язык)
и возвращает **до 3 подрядчиков с объяснением, почему именно они**. Ценность — в объяснении, а не в сортировке.

## Быстрый старт

```bash
pip install -r requirements.txt
streamlit run ui/streamlit_app.py          # интерфейс: http://localhost:8501
```

Другие способы:

```bash
python -m scripts.demo                     # все демо-сценарии в терминале
uvicorn app.api:app --reload               # HTTP API: http://localhost:8000/docs
pytest -q                                  # проверки из Definition of Done
```

LLM-объяснения (опционально): скопируйте `.env.example` в `.env`, укажите `ANTHROPIC_API_KEY` и `USE_LLM=1`.
Без ключа сервис полностью работает на шаблонных объяснениях из тех же фактов.

## Как устроен пайплайн

```
RecommendRequest
  │
  ▼
1. Пул           город + категория (вхождение: «Банкетный зал|Отель|Ресторан» находится по «Банкетный зал»)
  │                пусто → category_not_found
  ▼
2. Жёсткие       занят на дату · не берёт формат · цена «от» > бюджета · нет языка (если указан)
   фильтры         каждая причина записывается; никто не прошёл → no_match с разбивкой причин
  │
  ▼
3. Ранжирование  прозрачная сумма компонент (score_parts): специализация на формате, попадание в бюджет,
  │                совпадение описания, язык, длительность, штраф за проставленные данные.
  │                Сортировка (-score, id) → детерминизм
  ▼
4. Факты         СРАВНИТЕЛЬНЫЕ факты по top-3: «самый доступный в подборке», «единственный с казахским»,
  │                «дольше всех на площадке», конкретика из описания («356 свадеб», «ТОП-6 …»)
  ▼
5. Объяснение    LLM формулирует 1–2 предложения ТОЛЬКО из фактов (один вызов на выдачу, кэш)
  │                → валидатор: нет общих фраз, нет чисел не из фактов, объяснения не похожи друг на друга
  │                → при провале/без ключа: шаблон из тех же фактов
  ▼
RecommendResponse  status · message · shortage_reason · results[≤3] · rejections
```

**LLM не выбирает и не ранжирует** — это делает детерминированный код. Модель только переводит проверенные факты
в человеческий текст, поэтому она не может порекомендовать занятого подрядчика или выдумать цену.

### Три исхода

| status | когда | что видит пользователь |
|---|---|---|
| `matched` | есть ≥1 подходящий | карточки; если < 3 — `shortage_reason` с причиной |
| `category_not_found` | в городе нет такой категории | где эта категория есть |
| `no_match` | профили есть, но никто не прошёл | сколько отсеяно и почему + ближайшая свободная дата |

### Решения, которые мы приняли

- **Язык** (если указан) — жёсткое условие. **Длительность** — фактор ранжирования, `max_hours = null` не штрафуется
  (флористы, декор, сувениры не привязаны к часам).
- `price_from_kzt` — это цена «от», поэтому формулируем «от 650 000 ₸ укладывается в бюджет», а не «стоит».
- Профили с `price_imputed` / `city_imputed` помечаются в карточке и получают небольшой штраф в score.
- `Зарубежье` — отдельное значение города, как в данных.

## Данные

- `data/vendors.csv` — исходный датасет, 66 профилей (13 синтетических от организаторов).
- `data/synthetic_extra.csv` — наши дополнительные профили, `synthetic=True`. В UI синтетика отмечена зелёным бейджем.
- Окно календаря: 23.09.2026 — 31.12.2026.
