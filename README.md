# ASA — подбор event-подрядчиков

Локальные модули подбора и объяснений для задачи HackAlem (#79-lite). Они читают анонимизированный CSV из `data/providers.csv` (66 профилей) и возвращают до трёх карточек. Требуется Python 3.10+. Внешние пакеты для работы без модели не нужны.

## Быстрая проверка

```powershell
python test.py
python -c "from matching import recommend; from explanations import explain_response; print(explain_response(recommend({'city':'Алматы','date':'2026-10-15','event_format':'корпоратив','category':'Ведущий','budget_kzt':1000000})))"
```

`app.py` и веб-интерфейс в этом репозитории пока отсутствуют. Интеграция API или формы должна вызывать `explain_response(recommend(request))` и показывать `message`, `results[].reason`, `results[].price_from_kzt`, `results[].synthetic`, `results[].price_imputed` и `results[].city_imputed`. Функция `generateReason(candidate)` доступна отдельно для существующего командного контракта.

## Контракт

Обязательные поля запроса: `city`, `date` (`YYYY-MM-DD`, в диапазоне 23.09–31.12.2026), `event_format`, `category`, `budget_kzt` (целое число от нуля). Опциональные: `duration_hours` (положительное целое число) и `language`. Многозначные CSV-поля разделены `|`.

Ответ содержит `status` (`matched`, `category_not_found`, `no_match`), `message`, `counts` и `results`. В `counts` указаны `category_candidates`, `busy`, `over_budget`, `format`, `duration`, `price_missing`. Один кандидат может попасть в несколько счётчиков. Каждая карточка содержит исходные атрибуты, `score`, список подтверждённых `facts` с `id` и `text`, `reason`, `reason_source` (`llm` или `fallback`) и `evidence_ids`.

Город и категория определяют пул. Дата занятости, цена «от» выше бюджета, неподходящий формат и превышение `max_hours` исключают кандидата. Пустой `max_hours` не ограничивает длительность. Язык — необязательный сигнал ранжирования. Балл: 70, +10 если формат прямо упомянут в описании, +5 за совпавший язык, +5 за подтверждённую длительность. Дешевизна не повышает балл. При равенстве сортировка идёт по `id`; выдаются первые три.

Объяснение строится из конкретных фактов: формат, доступность по календарю, цена «от» и короткая **дословная выдержка из описания профиля**; при наличии добавляются язык и длительность. Выдержка — утверждение самого профиля, не внешняя проверка заслуг. Синтетический профиль прямо обозначается в причине и карточке. Проставленные при подготовке датасета цена/город помечены. Цена «от» — нижняя граница, не финальная смета.

## Необязательный LLM

Без ключа всегда работает быстрый детерминированный fallback. Чтобы модель выбирала, какие дополнительные подтверждённые факты подчеркнуть, задайте `OPENAI_API_KEY`; по умолчанию используется `gpt-4o-mini`, можно задать `OPENAI_MODEL`. Используется [OpenAI Responses API](https://developers.openai.com/api/docs/guides/structured-outputs) со структурированным JSON. Модель получает факты **одного** кандидата и возвращает только `evidence_ids`; конечный текст собирается локально из этих фактов. Это не даёт модели выбрать подрядчиков, поменять порядок или вставить непроверенный факт. Таймаут 2,5 секунды на карточку, ошибки API, неправильный JSON и недопустимые ID переключают карточку на fallback. Ключ храните в переменной окружения, не в репозитории.

## Демо-запросы

- Плотная категория: Алматы, `Ведущий`, `корпоратив`, 15.10.2026, бюджет 1 000 000 ₸. Для сравнения поменяйте дату: занятые кандидаты исчезнут.
- Редкая категория: Алматы, `Флорист`, `свадьба`, 18.10.2026, бюджет 300 000 ₸.
- Пустой результат: тот же запрос и бюджет `0` — категория есть, но цены не проходят. Категория, отсутствующая в городе, даст `category_not_found`.

Проверка `python test.py` покрывает CSV, фильтры, границу бюджета, календарь, стабильность порядка, три статуса и отказ модели с переходом на fallback.
