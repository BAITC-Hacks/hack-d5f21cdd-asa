# Команда: роли и план

Скелет уже работает сквозь весь пайплайн (`pytest -q` проходит, `scripts/demo.py` показывает все исходы).
Задача каждого — **улучшать свой модуль, не ломая контракт** `app/models.py`.

## Роли

### Участник 1 — движок подбора
Файлы: `app/catalog.py`, `app/matching/filters.py`, `app/matching/ranking.py`
- [ ] Проверить нормализацию на всех 66 строках (категории, пустой `max_hours`, даты)
- [ ] Подобрать веса `ranking.py` так, чтобы top-3 на демо-запросах был осмысленным
- [ ] Специализация: учитывать не только позицию формата, но и число форматов
- [ ] Тесты на граничные случаи: бюджет ровно = цене, дата вне окна, пустые поля

### Участник 2 — объяснения и UI
Файлы: `app/explain/*`, `ui/streamlit_app.py`
- [ ] Получить ключ API, включить `USE_LLM=1`, отладить промпт на 6 демо-запросах
- [ ] Улучшить `description_highlights`: вытаскивать стиль ведения, города работы, состав группы
- [ ] Новые сравнительные факты (например, «единственный, кто берёт и той, и свадьбу»)
- [ ] Валидатор: проверить, что LLM не противоречит полям профиля
- [ ] UI: читаемые карточки, три исхода визуально различимы

### Участник 3 — интеграция, данные, README, демо
Файлы: `app/recommender.py`, `app/api.py`, `scripts/demo.py`, `data/synthetic_extra.csv`, `README.md`
- [ ] Дописать 5–10 синтетических профилей в редкие категории (Флорист Астана, Отель, Ведущий церемонии…)
- [ ] Подобрать финальные демо-запросы, зафиксировать ожидаемую выдачу в README
- [ ] Проверить запуск с нуля по README на другом компьютере
- [ ] Схема пайплайна и рассказ для жюри (2–3 минуты)
- [ ] Замер времени ответа с LLM (< 10 с)

## Git

- Ветки: `feature/matching` (У1), `feature/explain-ui` (У2), `feature/integration` (У3).
- Перед работой: `git pull origin main`. Перед PR: `git merge main` в свою ветку, `pytest -q`.
- В `main` мержим только с зелёными тестами.
- `app/models.py` меняем только после договорённости в чате.

## План коммитов по часам

Каждый коммитит минимум раз в час законченный небольшой шаг:

| Час | У1 | У2 | У3 |
|---|---|---|---|
| 1 | тесты на граничные случаи | подключение LLM, первый промпт | синтетические профили |
| 2 | веса ранжирования | валидатор + кэш на реальных ответах | демо-запросы в README |
| 3 | специализация / описание в score | новые сравнительные факты | замер скорости, fallback |
| 4 | фиксы после интеграции | UI карточек и статусов | README: схема и запуск |
| 5 | финальная проверка DoD | полировка текстов | репетиция демо |

Примеры сообщений: `feat(matching): weight specialization by format count`,
`feat(explain): add unique-language comparative fact`, `docs: add demo scenarios`.
